1. SELECT and FROM

SELECT names the columns you want and FROM names the table. * means every column. AS renames a column in the result, and DISTINCT removes duplicate rows.

Try it: change the first query to SELECT *. Then try a calculated column: SELECT title, price * stock AS stock_value FROM books;

Checkpoint 1: predict before you run

SELECT title FROM books
WHERE price > 30 AND stock > 5;

Books over $30 are Data Visualization (0 in stock), Systems Analysis (7), Cloud Computing (4), Database Design (0) and Project Management (15). Which titles come back?

AND keeps a row only when both conditions are true. Only Systems Analysis (7) and Project Management (15) have more than 5 in stock.

3. Sorting with ORDER BY

ORDER BY sorts the result. Add DESC for largest first. You can sort by more than one column: the second breaks ties in the first.

Top N rows: MySQL and SQLite use LIMIT 3 at the end. Oracle uses FETCH FIRST 3 ROWS ONLY. Same idea, different words. See the tool tour below.

Checkpoint 2: predict before you run

In the query above, customers live in Dallas (Ana Lopez, Divya Rao), Frisco (Ethan Moore), Plano (Chen Wei) and Richardson (Ben Carter). Which name is listed last?

Rows sort by city first, alphabetically: Dallas, Frisco, Plano, Richardson. Richardson comes last, and Ben Carter is the only customer there.

4. Combining tables with INNER JOIN

A join matches rows from two tables using a shared key. INNER JOIN keeps only rows that have a match in both tables. Short aliases like b and p keep queries readable.

5. Keeping unmatched rows with LEFT JOIN

LEFT JOIN keeps every row from the left (first) table, even with no match. Missing values from the right table show as NULL. Use it to find things that are missing, like customers who never ordered.

Checkpoint 3: predict before you run

There are 5 customers and 6 orders. One customer, Ethan Moore, has never ordered. How many rows does the LEFT JOIN query above return?

The 6 orders each produce a row, and LEFT JOIN adds one more row for Ethan Moore with NULL as his order_id. An INNER JOIN would return only the 6.

Practice task: answer the manager's questions

The bookstore manager has three questions. Write one query for each, run it, then click Check. Column names do not matter, but the columns must be in the order asked.

Q1. Which Programming or Database books are in stock?

Return the title of every book in the Programming or Database category with stock above 0.

Q2. Which books cost under $40, and who publishes them?

Return title, price and publisher name for every book under $40, cheapest first.

Q3. Which orders did each customer place?

Return each customer's name and order_id, including customers who have never ordered.

All three questions answered. You are writing real SQL!

Stuck? Unlock hints one at a time.

Q1 needs IN (...) and AND stock > 0 in the WHERE clause. Remember single quotes around text.
Q2 is the INNER JOIN from section 4 plus WHERE b.price < 40 and ORDER BY b.price.
Q3 starts FROM customers c LEFT JOIN orders o ON .... If you get 6 rows instead of 7, you used an INNER JOIN.

Optional extension: the forgotten publisher

One publisher has no books in the store at all. Use a LEFT JOIN from publishers to books and a WHERE ... IS NULL condition to find its name. Your result should be a single row.
